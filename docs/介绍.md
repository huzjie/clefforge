# 多模态决策模型怎么落地：拆解 Cloudflare Clef，并把它做成一套能直接跑的框架

今天的热点是 Cloudflare 开源的**多模态决策模型 Clef（谱号）**。但我不打算复述"发布了什么、行业怎么看"——那些你去看新闻就行。这里只讲三件对同行真正有用的事：**决策模型到底改了什么架构、多模态是怎么接进去的、以及我把这些思路做成了一整套 `clefforge` 框架，填好配置就能跑**。

## 一句话看懂「决策模型」

传统大模型回答问题时，最后一层是对着整个词表（十几万维）做 softmax，生成下一个 token。决策模型只做一件事：**在 N 个候选选项里打分，返回"选第几个 + 置信度"**。

这个改动带来三个直接收益：

1. **输出空间从 15 万维压到 N 维**，延迟和成本都掉一个数量级（Clef 对标 Jev 就是靠这个）。
2. **置信度可以拿来用**：置信度低就降级、拒答，这是生成式模型给不了的编排信号。
3. **可微调**：RL 的奖励信号就是"选对没选对"，训练闭环极短。

工程上，这一刀砍在了「pointer head」上——把语言头换成指针头。

## 干货一：指针头怎么实现（可直接抄）

核心就十几行。把融合后的隐状态 `state` 和每个候选的表示 `option_vec` 做点积打分：

```python
class PointerHead:
    def __init__(self, dim):
        self.q = Linear(dim, dim)
        self.k = Linear(dim, dim)

    def logits(self, state, option_vecs):
        qs = self.q(state)
        return [sum(qs[j] * self.k(ov)[j] for j in range(dim)) for ov in option_vecs]

    def decide(self, state, option_vecs):
        logits = self.logits(state, option_vecs)
        best = argmax(logits)
        return best, softmax(logits)
```

**可复用要点**：工具选择、模型路由、护栏判定、意图分类——凡是"从固定选项里选一个"的任务，都能用同一个指针头替换生成式头。你不需要新模型，只需要换最后一层。

## 干货二：多模态别用 concat，用门控融合

Clef 比 Jev 多的关键能力是**原生视觉编码器**。很多人的第一反应是把图像向量和文本向量 `concat` 起来——维度翻倍、计算爆掉。Clef 的做法是学一个标量门：

```python
g = sigmoid(gate_logit)          # g ∈ [0,1]
fused = [g * t + (1 - g) * v for t, v in zip(text_vec, visual_vec)]
```

隐维度完全不变，模型自己学"这份输入该信图像多少"。配套的还有两种进阶融合：

- **交叉注意力**：文本 token 作为 query 去查视觉 token，把相关视觉信号拉进语言流。
- **MoE 视觉路由**：每个视觉 patch 只激活 top-k 专家，容量涨而计算不涨。

**踩坑提醒**：直接 concat 是新手最常见的多模态错误。门控融合实现简单、开销小、还能解释"模型看了多少图像"，建议默认用它。

## 干货三：决策模型的两个隐形 bug 和解法

### Bug 1：顺序偏差

LLM 决策模型系统性偏爱**靠前**的选项。同一组候选换个顺序，答案可能就变了。

**解法：排列评分**——把候选乱序多轮打分取平均：

```python
for s in range(n_shuffles):
    perm = shuffle(order, seed=1000+s)
    raw = score_fn([options[i] for i in perm])
    for pos, i in enumerate(perm):
        scores[i] += raw[pos]
avg = [s / n_shuffles for s in scores]
```

### Bug 2：过度自信

`max(softmax)` 经常虚高。直接拿它做门控会误判。

**解法：温度缩放 + ECE 复验**：

```python
# 网格搜索温度 T，最小化 ECE
p = [v ** (1/T) for v in probs]; p = normalize(p)
# 用 ECE（期望校准误差）验证置信度是否对齐真实准确率
```

**可复用要点**：只要你往下游输出概率，就必须过 ECE 校验。这两个 bug 各 10 行代码就能修，但没修就是线上事故。

## 干货四：把置信度接进「门控 + 快慢路由」闭环

置信度不要只拿来看，要变成编排动作：

```python
action = "accept"  if conf >= 0.7 else \
         "degrade" if conf >= 0.5 else "reject"
```

快慢路由按任务难度选模型：短查询、少选项走 9B 的 `clef-flash`，带图、长上下文走 27B 的 `clef`。难度特征选**可离线算、零成本**的信号（长度、选项数、是否带图），别为了路由再跑一遍模型。

## clefforge：把上面这些全部做成可运行的框架

这就是我今天交付的完整项目——`clefforge`（多模态决策模型训练与推理框架），不是示例、不是话题，是填好配置就能直接跑真代码的整套工程：

- **零依赖张量核** + **真指针头**（`cpu` 后端在张量核上真算点积打分）。
- **原生视觉编码器**（ViT patch 化 + 任意分辨率分片 + 投影器 + 门控融合 + MoE 路由）。
- **五后端**：`mock`（确定性 + 可训练）、`cpu`、`openai`、`vllm`、`transformers`。
- **RL 定制微调**：GRPO / PPO / DPO，演示里 `skill` 从 0.35 单调爬到 1.0、准确率从近随机到 1.0。
- **四组基准**：决策准确率 / 视觉参与度 / 路由选型 / ECE 校准。
- **Jev-API 兼容服务**：`POST /decide`，老 Jev 客户端可以无缝指过来。
- **CLI + Docker + K8s + Helm + CI**。

跑起来：

```bash
pip install -e .
python -m clefforge doctor          # 体检
python -m clefforge decide "选择工具" --options web_search python_exec
python -m clefforge train           # RL 微调，看准确率爬升
python -m clefforge bench           # 四组基准
python -m clefforge serve           # 起服务
```

**一句话总结**：决策模型 = 指针头 + 置信度闭环。把这五个字落地，就是把大模型从"聊天"变成"能进生产工作流的决策节点"。仓库地址见 README，欢迎照着改。
